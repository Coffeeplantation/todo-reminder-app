# Todoリマインダー 仕様書（デスクトップ Excel 版）

このドキュメントは `Todoリマインダー.xlsm`（VBA版）の挙動を正として記述したものです。
**ブラウザ版（`browser/index.html`）はこの仕様書に追随させること。** どちらかの版に機能追加・変更・バグ修正を行った場合は、必ずこの仕様書と、もう一方の実装の両方を更新する。

対象コード:
- `src/TodoReminder_VBA.bas`
- `src/KanbanSheetCtrl.cls`
- `src/KanbanHelper.cls`
- `src/ThisWorkbook.cls`

---

## 1. 全体構成

ブック `Todoリマインダー.xlsm` は3シートで構成される。

| シート名 | 役割 |
|---|---|
| `todoリスト` | 設定パネル + Kanbanボード（埋め込み） |
| `タスクリスト` | タスクの実データ（一覧表） |
| `名簿` | 担当者名 → メールアドレスの対応表 |

`Workbook_Open`（`ThisWorkbook.cls`）で、ブックを開くたびに以下を自動実行する。

1. `CheckAndSendReminders`（リマインダー判定・送信）
2. `SetupKanbanSheet`（Kanbanボードの再構築）

---

## 2. データモデル

### 2.1 `todoリスト` シート（設定）

| セル | 内容 | 既定値 |
|---|---|---|
| `A1` | タイトル文言（表示のみ） | `Todoリマインダー 設定` |
| `B4` (ラベル) / `C4` (値) | 既定のリマインド日数前 | `3` |
| `B5` (ラベル) / `C5` (値) | 署名（メール末尾に挿入） | `Todoリマインダーシステム` |
| `B8` (ラベル) / `C8` (値) | 自動メール送信 ON/OFF（文字列 `"ON"`/`"OFF"`） | `ON` |

- `C8` が `"OFF"`（大文字小文字を区別せず前後空白除去して比較）以外なら自動送信ONとみなす。
- `B4:C8` は角丸四角形の枠（`shp_settings_block`）で視覚的にグループ化される。
- `B11` セル以降の領域に Kanban ボード（フル表示 or 簡易表示）が図形として埋め込まれる。設定ブロックの行（4〜8行目）は Kanban のフル表示中は非表示になり、簡易表示時のみ表示される（後述）。

### 2.2 `タスクリスト` シート（列定義、A1に見出し行）

| 列 | 見出し | 内容 |
|---|---|---|
| A | No. | 連番（1始まり。空になったらそこでデータ終端とみなす） |
| B | タスク名 | 自由入力文字列 |
| C | 担当者名 | `名簿` シートの「名前」と一致させる想定 |
| D | 期日 | 日付（Excelシリアル値 or 日付として解釈できる値） |
| E | リマインド日数前 | 数値。0または未入力なら `todoリスト!C4` の既定値を使用 |
| F | ステータス | `未完了` / `進行中` / `完了` の3値（Kanbanの列に対応） |
| G | 送信済み | 空 / `済` / `アドレス不明` / `期日超過`（下記4章参照。マクロが自動更新） |
| H | 備考 | 自由入力（マクロは参照・更新しない） |

### 2.3 `名簿` シート（列定義、A1に見出し行）

| 列 | 見出し | 内容 |
|---|---|---|
| A | 名前 | `タスクリスト!C`（担当者名）と一致させるキー |
| B | メールアドレス | リマインドメールの送信先 |
| C | 部署 | 自由入力（マクロは参照・更新しない） |

## 3. 初回セットアップ（`SetupButtons`）

`Alt+F8` → `SetupButtons` 実行で、`todoリスト` シートに以下を配置する。

- **チェックボタン**（青、`btn_check`）: 「リマインド送信チェック」→ `CheckAndSendReminders` を実行
- **リセットボタン**（緑、`btn_reset`）: 「送信済みフラグをリセット」→ `ResetSentFlags` を実行
- 設定ブロックの枠 `shp_settings_block`
- Kanban ボード一式（`SetupKanbanSheet` 経由、3章参照）

再実行時は同名の既存図形を削除してから再生成する（多重生成防止）。

---

## 4. リマインダー判定・送信（`CheckAndSendReminders`）

`タスクリスト` の2行目から、A列（No.）が空になる行の直前まで処理する。

処理はループ内で1行ずつ、以下の優先順位で判定する（`GoTo NextRow` で次行へ）。

1. **期日（D列）が空** → スキップ（何もしない）
2. **期日が日付として解釈できない** → スキップ
3. **ステータス（F列）が「完了」** → スキップ
4. **送信済み（G列）が「済」** → スキップ（`skipCount` をカウント）
5. 残り日数 `daysLeft = 期日 - 本日`（日単位、`DateDiff("d", today, dueDate)`）を計算
   - `daysLeft < 0`（期日超過）:
     - **自動メール送信のON/OFFに関わらず** G列を `期日超過` にし、背景色を `RGB(255,99,71)`（トマト色）にする
   - `daysLeft <= reminderDays`（リマインド日数前に到達。`reminderDays` はE列、0以下ならC4の既定値）:
     - `名簿` シートを担当者名で検索し、メールアドレスを取得
     - メールアドレスが見つかれば `SendReminderEmail` を実行し、成功したらG列を `済` にして背景色 `RGB(144,238,144)`（薄緑）
     - メールアドレスが見つからなければ G列を `アドレス不明` にして背景色 `RGB(255,165,0)`（オレンジ）
   - 上記以外（まだリマインド日数に達していない）: 何もしない（G列は空のまま）

処理後、送信件数・スキップ件数をメッセージボックスで表示する。

### 4.1 メール送信（`SendReminderEmail`）

- 自動送信が **OFF** の場合: 実際の送信は行わず、判定結果（G列の更新）のみ行う（`SendReminderEmail` は常に成功扱いを返す＝ドライラン）。
- 自動送信が **ON** の場合: Outlook（`CreateObject("Outlook.Application")`）でメールを作成し、`.Display`（下書き表示。本番運用では `.Send` に変更する想定とコード内コメントにあり）。
  - 件名: `【リマインド】{タスク名}（期日：yyyy/mm/dd）`
  - 本文:
    - `daysLeft = 0` の場合: 「本日が期日のタスクがあります。ご確認をお願いいたします。」
    - それ以外: 「期日まで残り {daysLeft} 日となりました。ご対応をお願いいたします。」
    - 続けて罫線区切りで タスク名・期日（`yyyy年mm月dd日`）・残り日数を記載
    - 末尾に「このメールは{署名}より自動送信されています。」

### 4.2 フラグリセット（`ResetSentFlags`）

確認ダイアログ（Yes/No）の後、`タスクリスト` の全行についてG列の値と背景色をクリアする（`済`/`アドレス不明`/`期日超過` を全て空白に戻す）。

## 5. Kanban ボード（`KanbanSheetCtrl` / `KanbanHelper`）

`todoリスト` シート内に ActiveX コントロール（ListBox / CommandButton / Label）と図形を組み合わせて埋め込まれる、シート内蔵型の Kanban ボード。**2つの表示モード**を持つ。

### 5.1 表示モード

- **簡易表示（サマリー）**: 既定表示。列見出し「タスク名 / 期日 / 達成状況」+ 1本のリストボックス（`kb_sumlist`）で全タスクを一覧表示。クリックするとフルボードに切り替わる。
- **フル Kanban ボード**: 3列（未完了・進行中・完了）のリストボックスで構成される、ドラッグ&ドロップ可能な本格的な Kanban ボード。「簡易表示に戻る」ボタンでサマリーに戻る。

切替時、設定ブロック（4〜8行目）はフルボード表示中のみ表示され、簡易表示中は非表示になる（ボードがその行の位置に来るため）。図形は `Placement = xlFreeFloating` に固定し、行の表示/非表示でズレないようにしている。

### 5.2 フルボードの構成要素

| 列インデックス | 見出し | 見出し背景色 |
|---|---|---|
| 0 | 未完了 | `RGB(68,114,196)`（青） |
| 1 | 進行中 | `RGB(220,120,0)`（オレンジ） |
| 2 | 完了 | `RGB(60,150,60)`（緑） |

各列: 見出し + リストボックス（列: タスク名/担当者/期日/リマインド日数前/行番号の5列、後2列は非表示幅0）+ 「+ タスク追加」ボタン。

その他の要素:
- 列0↔1、列1↔2 間の **←→ 矢印ボタン**（選択中カードを隣接列へ移動）
- **選択を削除** ボタン（選択中カードを削除）
- **簡易表示に戻る** ボタン
- **タイトルバー**（ドラッグでボード全体を移動）
- **リサイズハンドル**（右下端をドラッグしてボード全体を拡大縮小、0.5倍〜2倍）
- **担当者ピル**（`名簿` シートの名前ごとに1つ。ドラッグして列にドロップすると、その担当者でのクイックタスク追加ダイアログが開く）
- ドラッグ中のゴーストラベル（カード/ピルの追従表示）

これら（矢印・タイトルバー・リサイズ・移動/リサイズ機能）は **Excelのシート埋め込み特有のUI** であり、レスポンシブなブラウザ画面には直接対応する概念がない。ブラウザ版では移動・リサイズ機能は対象外とし、代わりにCSSレイアウトで見やすく表示することで代替する（8章参照）。

### 5.3 カード操作

- **クリック選択**: リストボックス内の1行を選択すると、その列の見出しが黒（`RGB(20,20,20)`）にハイライトされる（他列は色を戻す）。
- **ドラッグ&ドロップ**: カードをドラッグして別列のリストボックス領域内でマウスアップすると、その列へ移動。ドラッグ判定の閾値は開始位置から6px以上動いた場合のみ（誤操作防止）。
- **矢印ボタンでの移動**: 選択中のカードがその矢印の移動元列と一致する場合のみ移動可能（そうでなければ警告メッセージ）。
- **タスク追加**（列の「+タスク追加」ボタン）: タスク名・担当者名（自由入力）・期日（`yyyy/mm/dd`、既定値は本日+7日）・リマインド日数前（既定 `3`）を順にダイアログで入力。
- **クイック追加**（担当者ピルをドロップ）: タスク名・期日・リマインド日数前を入力（担当者はドロップしたピルの名前で自動設定）。
- **削除**: 選択中のカードを確認ダイアログ後に削除。
- カードの移動・追加・削除のたびに `SaveToExcel` で `タスクリスト` シートへ即時反映（全行を一度クリアしてから列0→1→2の順に振り直して書き込む。No.列は書き込み順の連番で振り直される）。

### 5.4 データ同期

- **読み込み** (`LoadFromExcel`): `タスクリスト` の各行を、F列（ステータス）の値に応じて列0/1/2いずれかへ振り分ける（`完了`→列2、`進行中`→列1、それ以外→列0）。
- **書き込み** (`SaveToExcel`): 列0→1→2の順に全カードをタスクリストへ書き戻す。ステータス文言は列インデックスから `未完了`/`進行中`/`完了` に変換。書き込み時にG列（送信済み）は毎回空にリセットされる（＝カード移動のたびにリマインド送信判定がやり直しになる）。
- シートは `Protect DrawingObjects:=True, Contents:=False, UserInterfaceOnly:=True` で保護し、ユーザーが図形をマウスでドラッグして分解できないようにしている（コード側からの操作・ボタンクリック・リスト選択は影響を受けない）。

## 6. ステータス・送信済みフラグの値まとめ

**ステータス（タスクリスト!F列）**: `未完了` / `進行中` / `完了`

**送信済み（タスクリスト!G列）**:
| 値 | 意味 | 背景色 |
|---|---|---|
| （空） | 未判定 | なし |
| `済` | リマインドメール送信済み（または自動送信OFF下での送信対象確定） | 薄緑 `RGB(144,238,144)` |
| `アドレス不明` | 担当者名が名簿に見つからない | オレンジ `RGB(255,165,0)` |
| `期日超過` | 期日を過ぎている | トマト色 `RGB(255,99,71)` |

## 7. ブラウザ版との対応方針

- ブラウザ版 (`browser/index.html`) は本仕様書のデータモデル（設定・タスクリスト・名簿）とロジック（リマインダー判定、Kanban操作）を可能な限り忠実に再現する。
- **Outlook送信は不可**のため、ブラウザ版は常に「自動送信OFF」相当のドライラン動作とし、判定結果（G列相当のステータス）のみ更新する。送信内容（件名・本文）はログ/プレビューとして画面表示する。
- ボードの自由な移動・リサイズなど、Excelのシート埋め込み特有のUIは対象外。
- データ永続化はブラウザの `localStorage` を使用し、Excelファイルとは連携しない（開発・UI検証用途）。
- **同期ルール**: どちらかの実装（VBA / ブラウザ）に機能追加・仕様変更を行った場合は、必ず本ファイルを更新し、その内容をもう一方の実装にも反映すること。

### 7.1 ブラウザ版の表示モデル（現状は desktop 版と異なる）

ブラウザ版は 2026-07-07 時点で、5章の「簡易表示（サマリー表）⇔フル Kanban ボード」の2画面切替をやめ、**常時ボード表示に一本化**している。さらに、列の区分け軸を「ステータス（未完了/進行中/完了）」から **「期日の月」** に変更している。

- ページ上部のタイトルバー（アプリ名表示、JSONエクスポート/インポート、全データ初期化ボタン）は**廃止**しており、`タスク（月別ボード）` が画面の最上部から常時全幅表示される唯一のコンテンツになっている。データのエクスポート/インポート/初期化機能は現在提供していない。
- 「タスク（月別ボード）」自体の見出し・説明文、および担当者ピル（`山田太郎`等の名前表示行）も**廃止**しており、画面には月別パネル群（1月〜12月の12パネル）と「選択を削除」ボタンのみが表示される。
- **列＝ステータスではなく月**。タスクの期日（`due`）が属する年月ごとに1つの列（パネル）を生成する。期日が未設定/不正な値のタスクは「期日未設定」列にまとめる。
- 表示する月の範囲は、**常に「本日時点の年の1月〜12月」の固定カレンダー年**（例：本日が2026年なら2026-01〜2026-12の12列）。タスクの期日が表示年の範囲外（前年・翌年など）の場合は、そのタスクはどの列にも表示されない既知の制約がある。今月の列には「（今月）」の表示と枠線ハイライトを付ける。
- 「設定」「リマインダーチェック」「名簿」の3パネルは**画面には常に一切表示されない**（`.modal-only` により常時非表示）。「タスク（月別ボード）」だけが画面に常時表示される唯一のパネルである。
- 上記3パネルは、**各月パネルのフッターにある「設定・リマインダー・名簿」リンクから共有モーダルとしてのみ開ける**。リンクをクリックすると、既存のパネル要素（DOMノード）をそのまま共有モーダルへ移動して表示するため、複製ではなく常に単一のデータ・状態を共有する（どの月のリンクから開いても同じ内容・同じ操作結果になる）。モーダルを閉じるとパネルは元の位置に戻り、再び非表示になる。
- 月パネル同士は**CSSグリッドではなく完全な自由配置（絶対位置）**。各パネルは独立しており、見出し（`.kb-col-hdr`）部分をマウスドラッグすることで画面中の好きな位置へ自由に移動できる。位置は `state.monthPos[monthKey].{x,y,z}` として `localStorage` に保存され、次回表示時も維持される。初期表示時は4列×複数行のグリッド状の既定位置が割り当てられる。パネルを最後にドラッグした時ほど手前に表示される（`z` の値が大きいほど前面）。ボード領域（`#boardView`）はパネルの移動範囲に合わせて自動的にスクロール可能になる。
- 各月パネルは**既定で折りたたみ状態**（見出し＝月名のみ表示、`▶`アイコン付き）。見出しをクリックすると展開し（`▼`アイコンに変化）、カード・「+タスク追加」・設定/リマインダー/名簿リンク・リサイズハンドルが表示される。折りたたみ状態は `state.monthPos[monthKey].collapsed` として保存される。見出しのドラッグ（パネル移動）とクリック（開閉切り替え）は移動距離で判定して区別している。
- 展開中の各月パネルは**右下のハンドル（`.kb-col-resize`）をドラッグして大きさを自由に変更**できる。サイズは `state.monthPos[monthKey].{w,h}` として保存され、次回表示時も維持される（未変更のパネルは既定幅240px・内容に応じた自動高さのまま）。パネル内のカード領域は縦横ともスクロール可能なので、パネルを小さくしてもカードが失われることはない。**見出しの高さ程度まで縮めると、自動的に折りたたみ状態（月名のみ）に切り替わる**（flexboxの子要素は内容サイズより縮まないため、実際の描画サイズではなくドラッグ量から判定している）。
- 各月パネルの見出し背景色は、**現在月に近いほど濃い色、遠いほど薄い色**になるグラデーションで表示される（現在月からの月数差を最大11ヶ月分でグラデーション化）。期日未設定パネルは最も薄い色で扱う。現在月自体は、この配色に加えて従来通りオレンジ色の枠線でも強調される。濃い色・薄い色は「設定」パネルの2つのカラーピッカー（`state.settings.boardColorNear` / `boardColorFar`、既定値はそれぞれ `#2b3f63` / `#c4ced0`）で自由に変更できる。
- 各カードは既定で **タスク名 / 期日 / 達成状況（＝ステータス。バッジ表示）の3項目のみ**を表示する（担当者・リマインド日数前・送信済みは非表示）。列がステータスを表さなくなったため、達成状況はカード上のバッジでのみ判別できる。
- カードをクリックすると、そのカードだけ **担当者（編集可）/ 期日（編集可、yyyy/mm/dd）/ ステータス（編集可、ドロップダウン）/ リマインド日数前 / 送信済み状況** を含む詳細を展開表示する（再クリックで折りたたむ）。選択状態はカード削除（「選択を削除」）にもそのまま使われる。
- カードは1列内では**グリッド整列ではなく自由配置**（絶対位置）。マウスドラッグで同じ月パネル内の好きな位置に動かせ、位置は `task.pos.{x,y}` として `localStorage` に保存される。カードを最後に操作した（クリック/ドラッグした）時ほど手前に表示される（`task.z` の値が大きいほど前面）。
- カードを別の月列へドラッグして落とすと、期日の「日」はそのまま（対象月の末日を超える場合はクランプ）で年月だけが移動先に変わる（＝これがステータス列時代の「移動」に代わる、期日変更操作）。移動後の位置は、ドロップした位置に応じて移動先パネル内でクランプされる。ステータス自体は展開時のドロップダウンで変更する。
- 「+タスク追加」ボタンでの追加は月列に対して行われ、期日はその月の15日が既定値になる（新規タスクのステータスは常に「未完了」）。担当者はタスク追加/編集ダイアログでの手入力・選択のみで指定する（担当者一覧の表示やドラッグによるクイック追加は行わない）。
