# Todoリマインダー 仕様書（デスクトップ Excel 版）

このドキュメントは `Todoリマインダー.xlsm`（VBA版）の挙動を正として記述したものです。
**ブラウザ版（`browser/index.html`）はこの仕様書に追随させること。** どちらかの版に機能追加・変更・バグ修正を行った場合は、必ずこの仕様書と、もう一方の実装の両方を更新する。

対象コード:
- `src/TodoReminder_VBA.bas`
- `src/KanbanSheetCtrl.cls`
- `src/KanbanHelper.cls`
- `src/ThisWorkbook.cls`

---

## 1. 全体構成

ブック `Todoリマインダー.xlsm` は3シートで構成される。

| シート名 | 役割 |
|---|---|
| `todoリスト` | 設定パネル + Kanbanボード（埋め込み） |
| `タスクリスト` | タスクの実データ（一覧表） |
| `名簿` | 担当者名 → メールアドレスの対応表 |

`Workbook_Open`（`ThisWorkbook.cls`）で、ブックを開くたびに以下を自動実行する。

1. `CheckAndSendReminders`（リマインダー判定・送信）
2. `SetupKanbanSheet`（Kanbanボードの再構築）

---

## 2. データモデル

### 2.1 `todoリスト` シート（設定）

| セル | 内容 | 既定値 |
|---|---|---|
| `A1` | タイトル文言（表示のみ） | `Todoリマインダー 設定` |
| `B4` (ラベル) / `C4` (値) | 既定のリマインド日数前 | `3` |
| `B5` (ラベル) / `C5` (値) | 署名（メール末尾に挿入） | `Todoリマインダーシステム` |
| `B8` (ラベル) / `C8` (値) | 自動メール送信 ON/OFF（文字列 `"ON"`/`"OFF"`） | `ON` |

- `C8` が `"OFF"`（大文字小文字を区別せず前後空白除去して比較）以外なら自動送信ONとみなす。
- `B4:C8` は角丸四角形の枠（`shp_settings_block`）で視覚的にグループ化される。
- `B11` セル以降の領域に Kanban ボード（フル表示 or 簡易表示）が図形として埋め込まれる。設定ブロックの行（4〜8行目）は Kanban のフル表示中は非表示になり、簡易表示時のみ表示される（後述）。

### 2.2 `タスクリスト` シート（列定義、A1に見出し行）

| 列 | 見出し | 内容 |
|---|---|---|
| A | No. | 連番（1始まり。空になったらそこでデータ終端とみなす） |
| B | タスク名 | 自由入力文字列 |
| C | 担当者名 | `名簿` シートの「名前」と一致させる想定 |
| D | 期日 | 日付（Excelシリアル値 or 日付として解釈できる値） |
| E | リマインド日数前 | 数値。0または未入力なら `todoリスト!C4` の既定値を使用 |
| F | ステータス | `未完了` / `進行中` / `完了` の3値（Kanbanの列に対応） |
| G | 送信済み | 空 / `済` / `アドレス不明` / `期日超過`（下記4章参照。マクロが自動更新） |
| H | 備考 | 自由入力（マクロは参照・更新しない） |

### 2.3 `名簿` シート（列定義、A1に見出し行）

| 列 | 見出し | 内容 |
|---|---|---|
| A | 名前 | `タスクリスト!C`（担当者名）と一致させるキー |
| B | メールアドレス | リマインドメールの送信先 |
| C | 部署 | 自由入力（マクロは参照・更新しない） |

## 3. 初回セットアップ（`SetupButtons`）

`Alt+F8` → `SetupButtons` 実行で、`todoリスト` シートに以下を配置する。

- **チェックボタン**（青、`btn_check`）: 「リマインド送信チェック」→ `CheckAndSendReminders` を実行
- **リセットボタン**（緑、`btn_reset`）: 「送信済みフラグをリセット」→ `ResetSentFlags` を実行
- 設定ブロックの枠 `shp_settings_block`
- Kanban ボード一式（`SetupKanbanSheet` 経由、3章参照）

再実行時は同名の既存図形を削除してから再生成する（多重生成防止）。

---

## 4. リマインダー判定・送信（`CheckAndSendReminders`）

`タスクリスト` の2行目から、A列（No.）が空になる行の直前まで処理する。

処理はループ内で1行ずつ、以下の優先順位で判定する（`GoTo NextRow` で次行へ）。

1. **期日（D列）が空** → スキップ（何もしない）
2. **期日が日付として解釈できない** → スキップ
3. **ステータス（F列）が「完了」** → スキップ
4. **送信済み（G列）が「済」** → スキップ（`skipCount` をカウント）
5. 残り日数 `daysLeft = 期日 - 本日`（日単位、`DateDiff("d", today, dueDate)`）を計算
   - `daysLeft < 0`（期日超過）:
     - **自動メール送信のON/OFFに関わらず** G列を `期日超過` にし、背景色を `RGB(255,99,71)`（トマト色）にする
   - `daysLeft <= reminderDays`（リマインド日数前に到達。`reminderDays` はE列、0以下ならC4の既定値）:
     - `名簿` シートを担当者名で検索し、メールアドレスを取得
     - メールアドレスが見つかれば `SendReminderEmail` を実行し、成功したらG列を `済` にして背景色 `RGB(144,238,144)`（薄緑）
     - メールアドレスが見つからなければ G列を `アドレス不明` にして背景色 `RGB(255,165,0)`（オレンジ）
   - 上記以外（まだリマインド日数に達していない）: 何もしない（G列は空のまま）

処理後、送信件数・スキップ件数をメッセージボックスで表示する。

### 4.1 メール送信（`SendReminderEmail`）

- 自動送信が **OFF** の場合: 実際の送信は行わず、判定結果（G列の更新）のみ行う（`SendReminderEmail` は常に成功扱いを返す＝ドライラン）。
- 自動送信が **ON** の場合: Outlook（`CreateObject("Outlook.Application")`）でメールを作成し、`.Display`（下書き表示。本番運用では `.Send` に変更する想定とコード内コメントにあり）。
  - 件名: `【リマインド】{タスク名}（期日：yyyy/mm/dd）`
  - 本文:
    - `daysLeft = 0` の場合: 「本日が期日のタスクがあります。ご確認をお願いいたします。」
    - それ以外: 「期日まで残り {daysLeft} 日となりました。ご対応をお願いいたします。」
    - 続けて罫線区切りで タスク名・期日（`yyyy年mm月dd日`）・残り日数を記載
    - 末尾に「このメールは{署名}より自動送信されています。」

### 4.2 フラグリセット（`ResetSentFlags`）

確認ダイアログ（Yes/No）の後、`タスクリスト` の全行についてG列の値と背景色をクリアする（`済`/`アドレス不明`/`期日超過` を全て空白に戻す）。

## 5. Kanban ボード（`KanbanSheetCtrl` / `KanbanHelper`）

`todoリスト` シート内に ActiveX コントロール（ListBox / CommandButton / Label）と図形を組み合わせて埋め込まれる、シート内蔵型の Kanban ボード。**2つの表示モード**を持つ。

### 5.1 表示モード

- **簡易表示（サマリー）**: 既定表示。列見出し「タスク名 / 期日 / 達成状況」+ 1本のリストボックス（`kb_sumlist`）で全タスクを一覧表示。クリックするとフルボードに切り替わる。
- **フル Kanban ボード**: 3列（未完了・進行中・完了）のリストボックスで構成される、ドラッグ&ドロップ可能な本格的な Kanban ボード。「簡易表示に戻る」ボタンでサマリーに戻る。

切替時、設定ブロック（4〜8行目）はフルボード表示中のみ表示され、簡易表示中は非表示になる（ボードがその行の位置に来るため）。図形は `Placement = xlFreeFloating` に固定し、行の表示/非表示でズレないようにしている。

### 5.2 フルボードの構成要素

| 列インデックス | 見出し | 見出し背景色 |
|---|---|---|
| 0 | 未完了 | `RGB(68,114,196)`（青） |
| 1 | 進行中 | `RGB(220,120,0)`（オレンジ） |
| 2 | 完了 | `RGB(60,150,60)`（緑） |

各列: 見出し + リストボックス（列: タスク名/担当者/期日/リマインド日数前/行番号の5列、後2列は非表示幅0）+ 「+ タスク追加」ボタン。

その他の要素:
- 列0↔1、列1↔2 間の **←→ 矢印ボタン**（選択中カードを隣接列へ移動）
- **選択を削除** ボタン（選択中カードを削除）
- **簡易表示に戻る** ボタン
- **タイトルバー**（ドラッグでボード全体を移動）
- **リサイズハンドル**（右下端をドラッグしてボード全体を拡大縮小、0.5倍〜2倍）
- **担当者ピル**（`名簿` シートの名前ごとに1つ。ドラッグして列にドロップすると、その担当者でのクイックタスク追加ダイアログが開く）
- ドラッグ中のゴーストラベル（カード/ピルの追従表示）

これら（矢印・タイトルバー・リサイズ・移動/リサイズ機能）は **Excelのシート埋め込み特有のUI** であり、レスポンシブなブラウザ画面には直接対応する概念がない。ブラウザ版では移動・リサイズ機能は対象外とし、代わりにCSSレイアウトで見やすく表示することで代替する（8章参照）。

### 5.3 カード操作

- **クリック選択**: リストボックス内の1行を選択すると、その列の見出しが黒（`RGB(20,20,20)`）にハイライトされる（他列は色を戻す）。
- **ドラッグ&ドロップ**: カードをドラッグして別列のリストボックス領域内でマウスアップすると、その列へ移動。ドラッグ判定の閾値は開始位置から6px以上動いた場合のみ（誤操作防止）。
- **矢印ボタンでの移動**: 選択中のカードがその矢印の移動元列と一致する場合のみ移動可能（そうでなければ警告メッセージ）。
- **タスク追加**（列の「+タスク追加」ボタン）: タスク名・担当者名（自由入力）・期日（`yyyy/mm/dd`、既定値は本日+7日）・リマインド日数前（既定 `3`）を順にダイアログで入力。
- **クイック追加**（担当者ピルをドロップ）: タスク名・期日・リマインド日数前を入力（担当者はドロップしたピルの名前で自動設定）。
- **削除**: 選択中のカードを確認ダイアログ後に削除。
- カードの移動・追加・削除のたびに `SaveToExcel` で `タスクリスト` シートへ即時反映（全行を一度クリアしてから列0→1→2の順に振り直して書き込む。No.列は書き込み順の連番で振り直される）。

### 5.4 データ同期

- **読み込み** (`LoadFromExcel`): `タスクリスト` の各行を、F列（ステータス）の値に応じて列0/1/2いずれかへ振り分ける（`完了`→列2、`進行中`→列1、それ以外→列0）。
- **書き込み** (`SaveToExcel`): 列0→1→2の順に全カードをタスクリストへ書き戻す。ステータス文言は列インデックスから `未完了`/`進行中`/`完了` に変換。書き込み時にG列（送信済み）は毎回空にリセットされる（＝カード移動のたびにリマインド送信判定がやり直しになる）。
- シートは `Protect DrawingObjects:=True, Contents:=False, UserInterfaceOnly:=True` で保護し、ユーザーが図形をマウスでドラッグして分解できないようにしている（コード側からの操作・ボタンクリック・リスト選択は影響を受けない）。

## 6. ステータス・送信済みフラグの値まとめ

**ステータス（タスクリスト!F列）**: `未完了` / `進行中` / `完了`

**送信済み（タスクリスト!G列）**:
| 値 | 意味 | 背景色 |
|---|---|---|
| （空） | 未判定 | なし |
| `済` | リマインドメール送信済み（または自動送信OFF下での送信対象確定） | 薄緑 `RGB(144,238,144)` |
| `アドレス不明` | 担当者名が名簿に見つからない | オレンジ `RGB(255,165,0)` |
| `期日超過` | 期日を過ぎている | トマト色 `RGB(255,99,71)` |

## 7. ブラウザ版との対応方針

- ブラウザ版 (`browser/index.html`) は本仕様書のデータモデル（設定・タスクリスト・名簿）とロジック（リマインダー判定、Kanban操作）を可能な限り忠実に再現する。
- **Outlook送信は不可**のため、ブラウザ版は常に「自動送信OFF」相当のドライラン動作とし、判定結果（G列相当のステータス）のみ更新する。送信内容（件名・本文）はログ/プレビューとして画面表示する。
- ボードの自由な移動・リサイズなど、Excelのシート埋め込み特有のUIは対象外。
- データ永続化はブラウザの `localStorage` を使用し、Excelファイルとは連携しない（開発・UI検証用途）。
- **同期ルール**: どちらかの実装（VBA / ブラウザ）に機能追加・仕様変更を行った場合は、必ず本ファイルを更新し、その内容をもう一方の実装にも反映すること。

### 7.1 ブラウザ版の表示モデル（現状は desktop 版と異なる）

ブラウザ版は 2026-07-07 時点で、5章の「簡易表示（サマリー表）⇔フル Kanban ボード」の2画面切替をやめ、**常時ボード表示に一本化**している。さらに、列の区分け軸を「ステータス（未完了/進行中/完了）」から **「期日の月」** に変更している。

- ページ上部には**アプリバー（`.appbar`、sticky配置のすりガラスヘッダー）**を常時表示する（2026-07-09追加。旧タイトルバーとは別物）。内容は、アプリ名／**タスク検索ボックス**（タスク名・担当者名の部分一致。一致しないカードを `opacity: 0.22` で薄く表示する。`/` キーでフォーカス、`Esc` でクリア）／「＋タスク追加」（今月のタスク追加ダイアログを開く）／「背景」（背景を即時切替）／「リマインダー」「名簿」「設定」（各共有モーダルを開く）。JSONエクスポート/インポート/全データ初期化機能は引き続き提供していない。
- **キーボードショートカット**（入力中・ダイアログ表示中は無効）: `N`=タスク追加、`B`=背景切替、`/`=検索フォーカス、`Esc`=検索クリア→カード選択解除→メニューを閉じる（この優先順で1つずつ）。
- **トースト通知**（`#toasts`、`popover="manual"` でトップレイヤー表示するためモーダルより手前に出る）: タスク追加/削除、背景切替、リマインダーチェック実行時に右下へ約4.5秒表示する。タスク削除のトーストには**「元に戻す」アクション**が付く。
- 「タスク（月別ボード）」自体の見出し・説明文、および担当者ピル（`山田太郎`等の名前表示行）も**廃止**しており、画面には月別パネル群（1月〜12月の12パネル）と「選択を削除」ボタンのみが表示される。
- **列＝ステータスではなく月**。タスクの期日（`due`）が属する年月ごとに1つの列（パネル）を生成する。期日が未設定/不正な値のタスクは「期日未設定」列にまとめる。
- 表示する月の範囲は、**常に「本日時点の年の1月〜12月」の固定カレンダー年**（例：本日が2026年なら2026-01〜2026-12の12列）。タスクの期日が表示年の範囲外（前年・翌年など）の場合は、そのタスクはどの列にも表示されない既知の制約がある。今月の列には「（今月）」の表示と枠線ハイライトを付ける。
- 「設定」「リマインダーチェック」「名簿」の3パネルは**画面には常に一切表示されない**（`.modal-only` により常時非表示）。「タスク（月別ボード）」だけが画面に常時表示される唯一のパネルである。
- 「設定・リマインダー・名簿」および「+タスク追加」「パネルの色」は、**展開中パネルのヘッダー右端にある三本線メニューボタン（`.kb-col-menu-btn`）から開くドロップダウンメニュー**（`.kb-col-menu`）にまとめられている（2026-07-09より**アプリバーのボタンからも同じモーダル/ダイアログを開ける**）。メニューはカード領域の上に重なる形の絶対配置オーバーレイで、パネル自体のボックスサイズには影響しない。メニュー外をクリックすると自動的に閉じる。「設定」「リマインダー」「名簿」の3パネルは**画面には常に一切表示されない**（`.modal-only` により常時非表示）。「タスク（月別ボード）」だけが画面に常時表示される唯一のパネルである。メニューの「設定・リマインダー・名簿」をクリックすると、既存のパネル要素（DOMノード）をそのまま共有モーダルへ移動して表示するため、複製ではなく常に単一のデータ・状態を共有する（どの月のメニューから開いても同じ内容・同じ操作結果になる）。モーダルを閉じるとパネルは元の位置に戻り、再び非表示になる。
- タスクボードを載せているセクション（`.board-panel`）は**透明**（2026-07-10変更。背景・枠線・影・すりガラス効果なし）で、ネット背景画像がそのまま見える。可読性は各月パネル自体の白背景（`rgba(255,255,255,0.92)`）で確保する。
- 月パネル同士は**CSSグリッドではなく完全な自由配置（絶対位置）**。各パネルは独立しており、見出し（`.kb-col-hdr`）部分をマウスドラッグすることで画面中の好きな位置へ自由に移動できる。位置は `state.monthPos[monthKey].{x,y,z}` として `localStorage` に保存され、次回表示時も維持される。初期表示時は4列×複数行のグリッド状の既定位置が割り当てられる。パネルを最後にドラッグした時ほど手前に表示される（`z` の値が大きいほど前面）。ボード領域（`#boardView`）はパネルの移動範囲に合わせて自動的にサイズが広がるが、**縦横のスクロールバーは表示しない**（`overflow: hidden`）。パネルやカードのない空き領域をマウスドラッグすると、`scrollLeft`/`scrollTop` を直接操作してボード全体をパン移動できる（`#boardView` または `.kanban-columns` 自体をクリックした場合のみパン操作が発動し、パネル本体やカードのドラッグとは干渉しない）。
- **月パネル同士のドラッグ＆ドロップ結合**（2026-07-10追加）: 月パネルの見出しをドラッグして**別の月パネルの上に重ねてドロップすると、1枚の結合ボードにまとまる**（例: 8月を7月に重ねると「7,8月」ボード）。ドラッグ中は結合先候補がオレンジの内側枠（`.drop-target`）でハイライトされ、空きスペースへのドロップは従来通りの移動のみで結合しない。結合直後のトーストの「元に戻す」で取り消せ、恒久的な解除は結合ボードの三本線メニューの**「結合を解除」**から行う。
  - データモデル: 結合中の月の組は `state.monthGroups`（月キー配列の配列。例: `[["2026-07","2026-08"]]`）として保存。結合ボードのキーは月キーをソートして `+` で連結したもの（例: `2026-07+2026-08`）で、位置・見た目設定は `state.monthPos[結合キー]` に保持し、**結合先（ドロップされた側）の設定を引き継ぐ**。
  - **解除時の引き継ぎ**（2026-07-10追加）: 「結合を解除」すると、結合ボードの内容＝見た目設定と状態（`color`/`shape`/`border`/`fontSize`/`shadow`/`tileSize`/`icon`/`w`/`h`/`collapsed`。`INHERIT_POS_KEYS`）を**各月ボードにコピーして引き継ぎ**、結合ボードのあった位置から**横に並べて再配置**する（結合ボードで未設定の項目は各月の元の値のまま）。タスクは期日の月に従ってそれぞれの月ボードへ戻る。
  - 表示: 結合ボードには対象月すべてのタスクが表示され、達成率（%バッジ・進捗リング）も合算で計算。展開ヘッダーは「7,8月」（同年なら月番号をカンマ連結。今月を含む場合は「（今月）」付き＋オレンジ枠）、折りたたみタイルのバッジは「7,8」のような**横に伸びるピル型**になる。自動見出し色は先頭（最も早い）月を基準に算出し、個別色指定（メニューの「色」）も可能。
  - 操作: 結合ボードにさらに別の月パネル（または別の結合ボード）を重ねると3か月以上にも結合できる。「期日未設定」パネルは結合対象外。結合ボードへのカードのドロップは、タスクの期日の月が結合内に含まれていれば位置移動のみ、含まれなければ**先頭月への期日変更**として扱う。ダブルクリック追加・メニューの「+タスク追加」の既定月も先頭月になる。
- 各月パネルは**既定で折りたたみ状態**。折りたたみ時は横幅いっぱいの帯（バー）ではなく、**幅44pxの小さなタイルに縮小**され、**その月の月番号（1〜12。期日未設定パネルは「-」）を入れた円形バッジ**（`.kb-col-count-lg`）を中央に表示する（矢印アイコンや月名テキストは表示しない）。タイル自体（`.kb-col`）の外枠は、その月のタスク達成率（`status === "完了"` の件数 ÷ 件数、**10%刻み10段階に丸め**）を12時位置から**時計回りに**描く進捗リングを兼ねる。`col.style.padding` で3px分の隙間を空け、`conic-gradient(var(--green) 0deg <達成率×3.6deg>, var(--border) <同角度> 360deg)` を `col` の背景に敷くことで、隙間からリング状に覗かせている（内側の `.kb-col-hdr` は通常のパネル色で塗りつぶされる）。達成率100%ではタイルの周囲全体が `var(--green)` の線で囲まれる。タスクが1件も無い月は進捗リング表示なし（通常の1px枠線のみ）。タイルには達成率がツールチップ（`title`属性）としても表示される。タイルをクリックすると展開し、通常幅（既定240pxまたは保存済みの `state.monthPos[monthKey].w`）の横長ヘッダー（`▼ 月名`＋達成率バッジ（`.kb-col-pct-badge`。例：`50%`。タスクが無い月は非表示）＋右端の三本線メニューボタン。月番号バッジは展開時には表示しない）とカード領域・リサイズハンドルが表示される。折りたたみ状態は `state.monthPos[monthKey].collapsed` として保存される。見出しのドラッグ（パネル移動）とクリック（開閉切り替え）は移動距離で判定して区別している。
- 展開中の各月パネルは**右下のハンドル（`.kb-col-resize`）をドラッグして大きさを自由に変更**できる。サイズは `state.monthPos[monthKey].{w,h}` として保存され、次回表示時も維持される（未変更のパネルは既定幅240px・内容に応じた自動高さのまま）。パネル内のカード領域は縦横ともスクロール可能なので、パネルを小さくしてもカードが失われることはない。**ユーザーが明示的にリサイズした後（`state.monthPos[monthKey].h` が保存済みの場合）は、カード領域の最小高さ強制（既定の220px確保）を行わず、指定したサイズへ正しく縮小できる**（保存済みの高さが無い＝未リサイズの初期状態のみ、カードが隠れないよう220px以上を自動確保する）。見出しの高さ程度まで縮めると、自動的に折りたたみ状態（円形バッジのみ）に切り替わる（flexboxの子要素は内容サイズより縮まないため、実際の描画サイズではなくドラッグ量から判定している）。
- 各月パネルの見出し背景色は、**既定では現在月に近いほど濃い色、遠いほど薄い色**になるグラデーションで表示される（現在月からの月数差を最大11ヶ月分でグラデーション化）。期日未設定パネルは最も薄い色で扱う。現在月自体は、この配色に加えて従来通りオレンジ色の枠線でも強調される。グラデーションの濃い色・薄い色は「設定」パネルの2つのカラーピッカー（`state.settings.boardColorNear` / `boardColorFar`、既定値はそれぞれ `#2b3f63` / `#c4ced0`）で自由に変更できる。さらに、**三本線メニュー内の「色」カラーピッカーから、月ごとに個別の色を自由に指定できる**。指定した色は `state.monthPos[monthKey].color`（hex）に保存され、グラデーション色より優先して適用される（円形バッジ・折りたたみ時のタイルにも同じ色が反映される）。
- 三本線メニューには色のほかに、月ごとに見た目を調整できるセレクトを用意している（いずれも試験的な追加要素）。
  - **形（折りたたみ時）**（`state.monthPos[monthKey].shape`。既定 `square`＝角丸四角、`circle`＝折りたたみタイルを完全な円形にする。展開中パネルの形には影響しない）
  - **枠線**（`state.monthPos[monthKey].border`。既定 `normal`＝通常の1px実線、`double`＝4px幅の二重線 `border-style: double`）
  - **文字サイズ**（`state.monthPos[monthKey].fontSize`。`small`/`normal`/`large`。カード領域のフォントサイズを `--kb-font-scale` カスタムプロパティ経由で0.85〜1.25倍に拡縮する）
  - **影の強さ**（`state.monthPos[monthKey].shadow`。`none`/`normal`/`strong`。現在月のオレンジ枠と合成して `box-shadow` に適用）
  - **折りたたみの大きさ**（`state.monthPos[monthKey].tileSize`。`small`(32px)/`normal`(44px)/`large`(60px)。折りたたみタイルと中の丸バッジのサイズを変更する）
  - **アイコン**（`state.monthPos[monthKey].icon`。空/📌/⭐/🔥/📅。展開ヘッダーの月名の前、および折りたたみタイル右上隅の小さな絵文字として表示）
- ページ全体の背景は、**ネットから取得したランダム写真**（picsum.photos。APIキー不要、seedを毎回変えて取得）を全画面に敷き、**設定した間隔（分）で自動的に別の写真へクロスフェード切替**する（2026-07-09に日替わりグラデーション方式から変更）。実装は固定配置の2枚のレイヤー（`#bgA`/`#bgB`）を `opacity` トランジションで交互に入れ替える方式で、画像の読み込み完了（`Image.onload`）を待ってから切り替えるためちらつかない。その上に可読性確保用の薄い暗色スクリム（`#bgScrim`）を重ね、コンテンツのパネル群はすりガラス（`backdrop-filter: blur`）で背景から浮かせている。取得失敗・オフライン時は旧来の10種類のグラデーション（`FALLBACK_GRADIENTS`）からランダムに1つを適用する。設定パネルの「背景：ネット画像を使う」（`state.settings.bgOnline`、既定ON。OFFでグラデーションのみ）と「背景の自動切替間隔（分）」（`state.settings.bgIntervalMin`、既定10分）で制御でき、アプリバーの「背景」ボタンまたは `B` キーでいつでも手動切替できる。
- 各カードは既定で **タスク名 / 期日 / 達成状況（＝ステータス。バッジ表示）の3項目のみ**を表示する（担当者・リマインド日数前・送信済みは非表示）。列がステータスを表さなくなったため、達成状況はカード上のバッジでのみ判別できる。
- カードをクリックすると、そのカードだけ **担当者（編集可）/ 期日（編集可、yyyy/mm/dd）/ 対応月（編集可、ドロップダウン）/ ステータス（編集可、ドロップダウン）/ リマインド日数前 / 送信済み状況** を含む詳細を展開表示する（再クリックで折りたたむ）。
- **対応月セレクタ**（2026-07-10追加）: 展開したカードの「対応月」ドロップダウン（1月〜12月＋期日未設定）でタスクの月を直接選べる。変更すると `moveTaskToMonth` により期日の「日」を維持したまま年月だけが変わり（末日クランプあり）、その月のボードへ即座に移動する。**結合ボード内でタスクごとに月を振り分ける手段**として機能する（結合ボードへのタスク追加は先頭月既定のため、このセレクタで振り分け直す）。「期日未設定」を選ぶと期日がクリアされる。
- 「選択を削除」ボタンおよびページ下部のフッター（アプリ説明文）は**廃止**したままだが、2026-07-09より**カードの詳細展開内に「タスクを削除」ボタン**を提供する。削除は確認ダイアログなしで即時実行され、トーストの「元に戻す」で復元できる（トースト消滅後は復元不可）。
- カード領域の**空きスペースをダブルクリック**すると、その月を期日既定値としたタスク追加ダイアログが開く。
- カードは1列内では**グリッド整列ではなく自由配置**（絶対位置）。マウスドラッグで同じ月パネル内の好きな位置に動かせ、位置は `task.pos.{x,y}` として `localStorage` に保存される。カードを最後に操作した（クリック/ドラッグした）時ほど手前に表示される（`task.z` の値が大きいほど前面）。
- **カードのサイズ変更**（2026-07-10追加）: カード右下のハンドル（`.kb-card-resize`）をドラッグして大きさを自由に変更できる（最小 90×44px）。サイズは `task.size.{w,h}` として保存され、リロード後も維持される。カードは `overflow: hidden` のため縮めると内容が切れる。展開（選択）中は詳細が収まる既定レイアウト（幅220px・自動高さ）を優先し、カスタムサイズは適用しない（ハンドルも非表示）。リサイズ直後のクリックで選択がトグルしないようガードしている。
- **カードの月バッジ**（2026-07-10追加）: 各カードの期日の左に、そのタスクが属する月のバッジ（`.t-month`、例「7月」）を表示する。色はその月のボード見出しと同じ（`monthHeaderColor`。個別色指定・グラデーション設定を反映）。結合ボード上でもどの月のタスクかが一目で分かる。期日未設定タスクにはバッジを表示しない。
- カードを別の月列へドラッグして落とすと、期日の「日」はそのまま（対象月の末日を超える場合はクランプ）で年月だけが移動先に変わる（＝これがステータス列時代の「移動」に代わる、期日変更操作）。移動後の位置は、ドロップした位置に応じて移動先パネル内でクランプされる。ステータス自体は展開時のドロップダウンで変更する。
- 「+タスク追加」ボタンでの追加は月列に対して行われ、期日はその月の15日が既定値になる（新規タスクのステータスは常に「未完了」）。担当者はタスク追加/編集ダイアログでの手入力・選択のみで指定する（担当者一覧の表示やドラッグによるクイック追加は行わない）。
- **名簿のスコープと担当タスク表示**（2026-07-10追加）: 名簿は開き方でスコープが変わる。**アプリバーの「名簿」ボタンからは総合名簿**（タイトル「名簿（総合）」、全担当者）、**月ボードの三本線メニューの「名簿」からはそのボードのタスクに参加している担当者のみ**（タイトル「名簿（7月の参加者）」等。担当者追加ボタンは非表示、該当者ゼロなら「この月のタスクに参加している担当者はいません」）。スコープはモーダルを閉じるとリセットされる（`contactsScopeKey` 変数、非永続）。
  - 名簿の各行には**「関与タスク」列**（スコープ内でその担当者が `assignee` のタスク件数）を表示する。**行をクリックすると担当タスク一覧が展開**され（▸/▾ トグル）、各タスクが「タスク名（期日・ステータス）」のボタンとして並ぶ。
  - **タスクボタンをクリックするとモーダルを閉じてそのタスクへジャンプ**する：該当月（結合中なら結合ボード）を展開・最前面化し、カードを選択状態（詳細展開）にして `scrollIntoView` で表示位置へスクロールする。
- 三本線メニュー（`.kb-col-menu`）の `z-index` は 100000。選択中カードが `z-index: 1000+連番` を取るため、それより常に手前に表示する（2026-07-10修正）。
- **AIアシスタント**（2026-07-10追加、ブラウザ版のみ）: アプリバーの「🤖 AI」ボタンで右下にチャットパネル（`#aiPanel`、固定配置・高さ520px）を開閉できる。
  - 実装: Anthropic 公式SDK（`@anthropic-ai/sdk`）を `https://esm.run/@anthropic-ai/sdk` から動的importし、ブラウザから直接 Claude API を呼ぶ（`dangerouslyAllowBrowser: true`）。モデルは `claude-opus-4-8`、`thinking: {type:"adaptive"}`、ストリーミング応答（`client.messages.stream` + `finalMessage()`）。
  - APIキー: 設定パネルの「AI：Anthropic APIキー」（`state.settings.anthropicApiKey`）に入力。localStorage にのみ保存。未設定のまま送信するとエラーメッセージで設定を案内する。
  - コンテキスト: システムプロンプトに今日の日付・全タスク（id/名前/担当/期日/ステータス/リマインド日数/送信済み）・名簿・アプリ仕様の要約を毎ターン埋め込むため、AIは集計・期限チェック・提案などに直接答えられる。
  - ツール（tool use、手動ループ・最大8イテレーション）: `add_task`（名前・期日必須）/ `update_task`（id指定でステータス・期日・担当者・名前を変更、変更時は送信済みフラグをリセット）/ `delete_task` / `merge_boards`（月番号の配列を指定して月ボードを結合。指定月が結合済みならその結合ごとまとめる）/ `unmerge_board`（結合に含まれる月番号1つを指定して解除）。実行すると即座に `save()`＋`renderBoard()` され、トーストと、チャット内の「🔧 ツール名 を実行」表示で知らせる。システムプロンプトには結合中のボード一覧（`state.monthGroups`）も含まれる。
  - エラー処理: SDKの型付き例外（`AuthenticationError`/`RateLimitError`/`APIError`）で分岐した日本語メッセージを表示。失敗したターンは会話履歴から丸ごと巻き戻し、tool_use/tool_result が対にならない不整合を残さない。
  - 会話履歴はメモリ内のみ（リロードで消える）。「クリア」ボタンで手動リセットも可能。
